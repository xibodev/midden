Recommended starting point

Use the Midden app

A browser workspace for conversations, explicit tool permissions, drafts, previews and downloads.

Includes app + core + bundle.
No Go, Node.js or Python needed.

Windows / PowerShell

irm https://xibodev.github.io/midden/install.ps1 | iex

macOS / Linux

curl -fsSL https://xibodev.github.io/midden/install.sh | sh

Read before running: inspect Windows script / inspect Unix script.

Installs for your user account, then opens the browser. Keep the terminal running; Ctrl+C stops the host. Run midden-ui to start it again, or midden-ui --no-open to open the printed address yourself.

In Settings, choose an OpenAI-compatible connection (including a local server) or an Anthropic-compatible connection. Use an official API key, or a compatible local endpoint that may not need one.

Find models is a catalog, not verified inference. Check model makes a small tool-capability inference call with provider usage and no workspace reads. Exact manual model IDs work too.

Bring your existing host

Use Midden in your AI CLI

Install the same core and outcome guidance into an existing project. The host you already use keeps its own models, account and permissions.

Requires Python 3.9+ and a compatible AI CLI, installed and authenticated separately.

Windows / PowerShell

Invoke-WebRequest -Uri https://xibodev.github.io/midden/install.ps1 -OutFile .\midden-install.ps1
.\midden-install.ps1 -Mode cli -ProjectDir . -Host copilot

macOS / Linux

curl -fsSL https://xibodev.github.io/midden/install.sh -o midden-install.sh
sh midden-install.sh --mode cli --project . --host copilot

Inspect the downloaded script before the second command. The project defaults to the current directory.

copilot is the default host layout; claude and agents are alternatives. The existing receipt-based Python installer verifies inputs and records the files it owns.

Start a fresh conversation in that project and describe an outcome. No internal API choreography, mandatory MCP configuration or global permission grant is needed.

CLI mode uses the AI host's own authentication. It does not add native Copilot/Codex sign-in to the Midden app.

Only need session data? Select -Mode core / --mode core. The midden core never calls a model.

Updating an older installation? Stop the app, back up workspace/state, and read the migration guide before reusing data.

All install options, pinned versions and removal

Useful boundaries

The core stays deterministic.
The host does the AI work.

The core discovers, reads, searches, measures, collects and exports recorded material from Copilot CLI, Claude Code and OpenCode. It is independent of a model runtime.

The bundle supplies methods, templates and helpers. The app embeds the released Compa v1.0.0 kernel; an external AI CLI can instead execute that same bundle with its own tools.

Read the core contracts

Know what you are authorizing

Source investigation is read-only. File creation and other tool actions use the host's permission controls. Approved shell commands run with your account; the app is not an OS sandbox.

Native Copilot/Codex sign-in and a separately configured extension provider are not bundled in the app. Old native settings require explicit reconnection.

References prove origin, not truth. Credential filtering is not privacy clearance. Remote model calls send material through your chosen provider.

Compiled/runtime checks, local protocol fixtures and browser tests do not certify live AI content quality. Live acceptance needs legitimate credentials and inspection of real outputs.

Install deliberately

Matching files. Verifiable updates.

Use one release's app/core payloads, bundle and checksums. Installation is per-user; workspace and host state live outside its root. Verify, upgrade and uninstall operate on owned files, not your working data.

Pinned scripts and the release candidate

Use the pinned v0.3.1 PowerShell script or v0.3.1 shell script, then select -Version v0.3.1 / --version v0.3.1.

The same bootstraps are available as latest PowerShell and latest shell release assets. latest is not a prerelease selector.

For staging, choose v0.3.1-rc.1 explicitly and use separate install, workspace and state directories.

Checksums establish integrity against a manifest, not publisher authenticity. The v0.3.1 release binaries are unsigned; a matching checksum is not a publisher signature. No administrator access, execution-policy bypass or automatic language-runtime/renderer installation is required.
